# Новостной бот для Telegram

Бот читает новые посты из публичных каналов-доноров, убирает рекламу и чужие подписи, чистит ссылки, по возможности переписывает текст и публикует результат в один ваш канал. Это перепубликация очищенных новостей в канал, которым вы управляете. Бот не читает личные чаты, не пишет подписчикам и не скрывает, что канал собирает новости из других источников.

Один процесс: Telethon (пользовательская сессия) читает доноров, aiogram публикует в целевой канал от имени бота. Состояние лежит в SQLite.

## Что нужно один раз

### Токен бота

В [@BotFather](https://t.me/BotFather) выполните `/newbot` и запишите токен в `BOT_TOKEN`. Добавьте этого бота администратором двух каналов, с правом публиковать сообщения: целевого канала новостей и канала проверки (`log.channel`). В оба канала бот пишет сам. Без прав администратора посты и кнопки не появятся.

### api_id и api_hash

На [my.telegram.org](https://my.telegram.org) откройте API development tools и запишите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Пользовательская сессия нужна, потому что бот Bot API не может читать чужие каналы. Сессия используется только чтобы читать каналы из `donors`.

### Строка сессии

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export TELEGRAM_API_ID=...
export TELEGRAM_API_HASH=...
python -m newsbot.login
```

Скрипт спросит телефон и код. Если на аккаунте включён облачный пароль, он ждёт этот пароль и не считает код неверным. Строка сессии записывается в `TELEGRAM_SESSION` в `.env` и не печатается. Это секрет: только `.env`, не git и не чат.

### Конфиг и окружение

```bash
cp config.example.yaml config.yaml
cp .env.example .env
```

Если `.env` уже заполнен, не затирайте его копией примера.

В `config.yaml` заполните:

- `target.channel` — канал новостей, `@username` или числовой id;
- `log.channel` — канал проверки, туда падает готовый пост с кнопками;
- `owner_id` — ваш числовой Telegram user id;
- `donors` — публичные username каналов, без `@` (список может быть пустым; владелец добавляет их в чате);
- `signatures` — свой футер, ссылка на канал, хештеги. Пока блок не заполнен, подпись не добавляется.

В `.env` заполните `BOT_TOKEN`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION`. `OPENAI_API_KEY` необязателен. Файл `.env`, `config.yaml` и файлы `*.session` в git не попадают.

Если `OPENAI_API_KEY` пустой или в конфиге `rewrite.enabled: false`, модель не вызывается: пост всё равно очищается и публикуется. Если ключ задан, но запрос упал, в канал уходит очищенный оригинал, а ошибка пишется в журнал.

## Запуск

`config.yaml` должен уже существовать, иначе Docker создаст вместо файла каталог.

```bash
docker compose up -d --build
docker compose logs -f
```

Один контейнер. Второй экземпляр на той же базе даст дубли. Остановка: `docker compose down`.

## Команды владельца

`/start` и `/help` отвечают всем: бот на связи и что делают кнопки в канале проверки. Рядом с полем ввода появляется меню команд. Владельцу в личке ещё ставится нижняя клавиатура: Статус, Доноры, Пауза, Продолжить, Помощь. Чужим на команды владельца бот отвечает «нет доступа», а не молчит.

- `/status` — пауза или работа, доноры, сколько постов на проверке, последние ошибки и журнал;
- `/pause` — не класть новые посты в канал проверки (кнопки у уже лежащих там постов работают);
- `/resume` — снова отправлять очищенные посты на проверку;
- `/donors` — список доноров. Кнопки под сообщением: «Добавить», и у каждого канала «Удалить» и «Редактировать». Удаление спрашивает подтверждение. Добавить можно публичный канал (`@username` или ссылка t.me); личные чаты и группы не принимаются. Редактирование меняет username и включает или выключает канал. Своя подпись донора, если она уже была в конфиге, сохраняется. Список пишется в `config.yaml`;
- `/preview <username>` — прогнать пайплайн по последнему посту донора и прислать результат в личку, без публикации и без отметки «уже видели».

## Как обрабатывается пост

1. Служебные сообщения, пустые посты и реклама отбрасываются. Реклама — это явная эвристика из `ad_filter`: фразы из списка (`реклама`, `erid`, `промокод` и другие), слишком много http(s)-ссылок или регулярное выражение. Отдельного «умного» скоринга нет. Новость, в которой есть фраза из списка, тоже будет отброшена — список нужно подстроить.
2. Из текста вырезаются шаблоны донорских подписей. Строка с маркером из `trailing_markers` и всё ниже неё считаются хвостовым промоблоком.
3. Ссылки нормализуются: параметры `utm_*` и список `strip_params` удаляются, домены из `domain_rewrite` подменяются, домены из `blacklist_domains` выкидываются.
4. Если ключ модели задан, текст переписывается по-русски в тоне из конфига. Факты нужно сохранять, выдумывать нельзя. Длина, промпт и флаг подписи к медиа задаются в `rewrite`.
5. Похожие новости из разных доноров не кладутся на проверку повторно, если такой сюжет уже был отправлен в канал новостей. Сравнивается отпечаток нормализованного текста и коэффициент Жаккара по словам в окне `dedupe.window_hours`. Короткие тексты совпадают только целиком.
6. В конец добавляется выбранный шаблон подписи (`signatures.templates`, по умолчанию `signatures.default`), если он задан. У донора может быть свой шаблон.
7. Готовый текст и фото попадают в канал проверки, а не сразу в канал новостей. Под постом три кнопки, их нажимает только `owner_id`: «Отправить» публикует этот текст в целевой канал и убирает кнопки, подписывая id сообщения; «Редактировать» отвечает на нажатие и просит ответить новым текстом на этот пост в канале проверки, не в личке; ответ владельца меняет превью и оставляет кнопки, не публикуя; «Отклонить» снимает кнопки и ничего не публикует. Чужие нажатия и чужие ответы игнорируются. Альбом — медиагруппа до 10 фото, кнопки на отдельном сообщении под ним.

Подпись к фото обрезается до 1024 символов, обычный текст — до 4096. Футер при обрезке сохраняется. Между отправками в канал новостей выдерживается `rate_limit`. В SQLite пишутся превью, состояние (pending / sent / rejected), канал-источник, id исходных сообщений и id сообщений в вашем канале.

## Тесты

Сеть и Telegram не нужны.

```bash
pip install -r requirements-dev.txt
pytest
```

## Ограничения

В `donors` указывайте только публичные каналы. Группы, личные чаты и рассылки бот не обходит и не шлёт. Во время паузы новые посты в канал проверки не попадают. Новый текст превью — это ответ на сам пост в канале проверки.
